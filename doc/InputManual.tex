Three files are required for running a trajectory.
\begin{enumerate}
	\item The main input file containing all of the options for the program.
	\item A file containing the initial geometry.
	\item A file containing the initial velocity.
\end{enumerate}

The name of the main input file is passed to the program through the command line (if no file name is passed, the default input file is dynamics.in). The file is split into sections with options concerning parts of the program. For details on the options, see below. The minimum input is the \$method section which gives the path to an interface script which communicates between the dynamics and the electronic structure package (see section \ref{sec:interface}).
In the case of QM/MM dynamics, a second script is used to communicate to the MM package. The QM(MM) driver expects a directory which contains all the input required for a QM(MM) calculation. By default this directory is "qmdir"("mmdir"), but can be changed using the QMDIR(MMDIR) environment variables.

The geometry file (called "geom" by default) contains one line for each atom. Each line contains the atom symbol, atom mass, coordinates and type of atom. The type in the final column is either "q" (for QM atoms) or "m" (for MM atoms). The velocity file contains just the initial velocity vector for each atom.

A stopped or finished trajectory can be continued by adding the \$restart keyword to the input file. The trajectory then continues from the backup file (see bufile and buinterval), and gives the same results as an uninterrupted run. The geometry file is still read for the atoms of the system, but the geometry and velocities are taken from the backup, and the velocity file is not needed. The results directory of the previous run is required, and its output files are cut back to their state at the time of the backup before new data is appended. The input must otherwise be the same as for the previous run. Only options which do not change the dynamics up to the saved point may differ, such as max\_time to extend a finished trajectory; the potential, the surface hopping method, the number of states and the print options must stay the same. A trajectory which ended because of a condition other than max\_time (for example a target state with end\_state\_time 0, or a dynamics.stop file) continues for at least one step after the restart.

\section*{Program options} \label{sec:options}
\paragraph{method}
Section \$method contains paths to the driver programs for running the calculations.  \newline
\$method

\begin{tabularx}{\textwidth}{ m{2.5cm} X }
qm				&
	\textbf{No default.} \newline
	Command which runs the external program that computes the potential (see section \ref{sec:interface}). A command with arguments is given in quotes, which are removed. Example: qm "eval\_point vibronic\_coupling LVC.template". Only singlet states (multiplicity 1) are available, and there is no diabatic basis (print options 21 and 31 and istate\_basis diabatic are not available). Either qm or qlib is required.  \\

mm				&
	\textbf{No default.} \newline
	Command line call for MM calculation driver.  \\

overlap &
    	\textbf{No default.} \newline
	Command line call for code to calculate the overlap matrix. Run "cis-overlap.exe -h" for command line options. \\

qlib &
    \textbf{No default.} \newline
    Use fortran subroutine(s) instead of the standard file-based QM interface. Currently the only option is "quantics" if the code
    was compiled with the "-DQUANTICS=ON" option. For Quantics direct dynamics operators, the potential is interpolated from the
    Quantics database, whose directory (as given in the Quantics input) is taken relative to the trajectory directory. \\

seed \# &
	\textbf{-1} \newline
	Give a seed for the random number generator. If seed is < 0, a seed is generated automatically based on the current time and job ID. \\
\end{tabularx}

%System section
\paragraph{system}
Section \$system contains information about the dimensions of the system and the initial conditions. \newline
\$system

\begin{tabularx}{\textwidth}{ m{2.5cm} X }
nstate \# [\# ...]		&
    \textbf{all states of the potential} \newline
    Number of states of the dynamics: the number of spin-free states of each multiplicity given by the multiplicity keyword, for example "nstate = 2 1" with "multiplicity = 1 3" for two singlets and one triplet. \newline
    For potentials which define their own states (vibronic coupling templates and model potentials), nstate selects a subset of them: the lowest nstate eigenstates of the spin-free Hamiltonian (MCH states) of each multiplicity. A multiplicity which is not given has no states in the dynamics. Requesting more states than the potential has is an error. The potential is still evaluated with all of its states. The adiabatic states are the eigenstates of the Hamiltonian, including the spin-orbit couplings, within the selected MCH states, as in on-the-fly dynamics with a limited number of states. They are not eigenstates of the full model, and the overlaps between the adiabatic states of two steps are not an orthogonal matrix. A warning is printed when their smallest singular value is below 0.9, which happens when the highest selected state crosses a state which is not selected. The diabatic basis always has all states of the potential. \newline
    For Quantics operators, nstate and multiplicity describe all states of the operator and have to match it. A subset is not available.  \\

multiplicity \# [\# ...]		&
    \textbf{1} \newline
    Multiplicity ($2S+1$) of each block of states given by nstate. Each multiplicity can be given once.  \\

truncated\_gradient		&
    \textbf{exact} \newline
    Gradients and nonadiabatic coupling vectors of the adiabatic states when the dynamics runs on a subset of the states of the potential (nstate) with spin-orbit couplings. Possible options: \newline
	\tabitem [exact] Derivatives of the energies of the dynamics. They include the term from the change of the selected MCH states with the geometry (spin-orbit couplings between selected and unselected MCH states times their nonadiabatic couplings). The total energy is conserved. \newline
	\tabitem [hellmann\_feynman] Without this term, $\mathbf{U}^T (\partial \mathbf{H} / \partial x) \mathbf{U}$ for the adiabatic states $\mathbf{U}$. This is the approximation of on-the-fly dynamics, where the states which are not selected are not known. \newline
	The option has no effect with all states, without spin-orbit couplings or in the mch basis (LZSH).  \\

istate \#		&
    \textbf{nstate} \newline
    Initially populated state, a state of the basis given by istate\_basis. In a FSSH calculation, the initial wave function coefficient of the initial active state will be 1, while others will be 0. \newline
    \textbf{istate file name}: read the state from the file name.  \\

istate\_basis	&
    \textbf{method} \newline
    Basis of istate. Possible options: \newline
	\tabitem [method] The basis of the surface hopping method (adiabatic for FSSH, mch for LZSH, sh\_basis for \$surfhop off). istate is the initial active state. \newline
	\tabitem [diabatic] Diabatic states, numbered in the order of the source of the potential (for Quantics, all spin components of a state are consecutive; for vibronic coupling templates and model potentials, the ZagHop order). \newline
	\tabitem [adiabatic] Eigenstates of the Hamiltonian with spin-orbit couplings, within the states of the dynamics. \newline
	If istate\_basis is not the basis of the method, istate is projected onto the states of the method basis at the initial geometry, and the initial active state $a$ is drawn with probability $|\langle i | a \rangle|^2$ (as in zagpy sample state). For LZSH, a diabatic state is projected through its spin-free state. With effective spin states, a diabatic spin component of the source is mapped to its effective state. If the dynamics runs on a subset of the states of the potential (nstate), a diabatic state is only partly in the states of the dynamics: the probabilities are divided by their sum, which is printed, and a state without weight in the states of the dynamics is an error. Not used on restart.  \\

geometry 		&
    \textbf{geom} \newline
    Name of the geometry file, containing the masses and initial positions of the atoms.  \\

velocity		&
    \textbf{veloc} \newline
    Name of the velocity file, containing the initial velocities of the atoms.  \\

ndim \#		&
    \textbf{3} \newline
    Number of dimensions per atom.  \\

classical\_coordinates		&
    \textbf{Coordinates of the potential} \newline
    Coordinate system in which the classical propagation is performed. The geometry and velocity files are given in these coordinates. If they differ from the coordinates in which the potential is evaluated, the potential evaluator transforms the geometry and returns the gradients and nonadiabatic coupling vectors in the coordinates of the classical propagation. Currently only "cartesian" is supported for the vibronic coupling potential ("normal\_modes"), which requires the "Geometry" and "Mass-weighted normal modes" sections in the V0 file. The atoms (order, symbols and masses) in the geometry file need to match the "Geometry" section. The normal modes are only invariant to infinitesimal rotations about the reference geometry, so the initial geometry should be given in its frame (or use orient = 2). \\

cartesian\_frame		&
    \textbf{fixed} \newline
    Frame in which Cartesian geometries are transformed to normal modes, for the vibronic coupling potential with classical\_coordinates = cartesian. \newline
    \tabitem [fixed] the geometry is used as given, in the frame of the reference geometry. The potential is only invariant to infinitesimal rotations about the reference geometry, and the dynamics are equivalent to propagating the normal modes directly (no rotation-vibration coupling). \newline
    \tabitem [eckart] the geometry is first rotated into the Eckart frame of the reference geometry (mass-weighted Kabsch alignment). The potential is invariant to any rotation, so the angular momentum is conserved and rotation-vibration coupling is included. Not available for linear molecules. \\

variable\_nstate \#		&
    \textbf{0} \newline
    Option to change number of states included in calculation on-the-fly. \newline
    \tabitem [0] always use \textbf{nstate} states. \newline
    \tabitem [1] reduce number of states by removing high lying states from the calculation when the absolute value of the corresponding coefficient in the total wave function drops below 0.01. States higher than $\textbf{min\_nstate}$ and $\textbf{cstate}+1$ can be removed. \\

min\_nstate \#		&
    \textbf{0} \newline
    Minimum number of states in the QM system. For $\textbf{variable\_nstate}=1$. \\

max\_nstate \#		&
    \textbf{0} \newline
    Maximum number of states in the QM system. For $\textbf{variable\_nstate}=1$.  \\

\end{tabularx}

\paragraph{dynamics}
Section \$dynamics contains options for the propagation of the nuclear coordinates. \newline
\$dynamics

\begin{tabularx}{\textwidth}{ m{3.5cm} X }
time/max\_time \#	&
	\textbf{10.0} \newline
	Total time (in fs) for the propagation of nuclear coordinates.  \\

tstep \#		&
	\textbf{0.5} \newline
	Time step (in fs) for the propagation of nuclear coordinates.  \\

orient \#		&
	\textbf{0} \newline
	Select how to handle translation/rotation. Only available for Cartesian coordinates (ndim = 3). \newline
	\tabitem [0] do nothing. \newline
	\tabitem [1] keep molecule in center of mass and project translation from the velocity. \newline
	\tabitem [2] as [1], and also project rotation from the velocity. If the potential is defined relative to a reference geometry (vibronic coupling potential with classical\_coordinates = cartesian and cartesian\_frame = fixed), the initial geometry and velocity are first rotated into the frame of the reference geometry (mass-weighted Kabsch alignment, which satisfies the Eckart conditions), and rotations are projected about the reference geometry. 	\textbf{0} \newline

max\_toten\_d \#	&
	\textbf{1.0} \newline
	End dynamics if drift in total energy is larger than \# eV. \\

max\_toten\_d\_step \#	&
	\textbf{0.2} \newline
	End dynamics if change in total energy during a single step is larger than \# eV. \\

%Surfhop section
\paragraph{surfhop}
Section \$surfhop selects the surface hopping method and contains options for the surface hopping procedure and the propagation of the electronic wave function. The method is given on the section line. Without a method, or without the section, LD-FSSH is used. \newline
\$surfhop (method) \newline
Possible methods: \newline
	\tabitem [off] No surface hopping. Dynamics are performed on the initial state of the basis given by sh\_basis (adiabatic by default). \newline
	\tabitem [lz] Landau-Zener surface hopping between neighbouring states of the same group, at minima of their gap with the active state. Shorter steps can be inserted around a gap minimum (see lz\_prob\_conv), but output is only written at multiples of tstep. \newline
	\tabitem [ld-fssh] Fewest switches surface hopping with the electronic wave function propagated in the locally diabatic basis. (Default.) \newline
	\tabitem [a-fssh] Fewest switches surface hopping in the adiabatic basis. (Not available in this version.)


\begin{tabularx}{\textwidth}{ m{2.5cm} X }
sh\_basis	&
	\textbf{adiabatic}	\newline
	Off only. Basis of the state on which the dynamics are performed. The initial state (istate) is a state of this basis. Possible options: \newline
	\tabitem [adiabatic] Eigenstates of the Hamiltonian with spin-orbit couplings, within the states of the dynamics (the diagonal representation of SHARC). \newline
	\tabitem [diabatic] Diabatic states of the potential. All states of the potential, also when the dynamics runs on a subset of the states (nstate). \newline
	\tabitem [mch] Eigenstates of the spin-free Hamiltonian (molecular Coulomb Hamiltonian, MCH) within each multiplicity, one state for each spin-free state of the dynamics. Unlike in the MCH representation of SHARC, the spin components of a multiplet are not separate states. This basis was called spin\_free in earlier versions. \\

tdse\_steps \#	&
	\textbf{1}	\newline
	LD-FSSH only. Number of substeps for electronic wave function propagation between the nuclear time step at $t$ and at $t + \Delta t$. The Hamiltonian is interpolated linearly during the propagation. Probabilities printed in the prob file are sums of probabilities from each substep. \\

prob\_formula	&
	\textbf{sharc}	\newline
	LD-FSSH only. Formula for the hopping probabilities. Possible options: sharc, ld01, ld01\_l, ld19. \\

decoherence		&
	\textbf{edc}	\newline
	LD-FSSH only. Method used for applying a decoherence correction to the electronic wave function. Possible options: \newline
	\tabitem [off] No decoherence correction. \newline
	\tabitem [edc] Energy based decoherence scheme. \\

overlap			&
	\textbf{npi}	\newline
	Use overlaps between wave functions at the start and end of nuclear time step to calculate time-derivative couplings (TDCs) between states. The TDCs can be interpolated during the propagation between nuclear time steps. Possible options: \newline
	\tabitem [constant] Use the finite-differences method to calculate TDCs at $ t + \Delta t / 2 $ and use this value for all substeps. \newline
	\tabitem [linear] Use linear interpolation/extrapolation between the TDCs at $ t - \Delta t / 2 $ and $ t + \Delta t / 2 $. \newline
	\tabitem [npi] Use the norm preserving interpolation method to calculate the average TDCs during the nuclear time step and use this value for all substeps.\\

phase			&
	\textbf{2} \newline
	Method of handling phase of wave functions during dynamics. \newline
	\tabitem [0] No phase matching. \newline
	\tabitem [1] Match phase of adiabatic states. \newline
	\tabitem [2] Match phase of diabatic states (using assignment problem solution). \\

nadvec			&
	\textbf{linear}		\newline
	Use nonadiabatic coupling vectors to calculate time-derivative couplings between states.  The TDCs can be interpolated during the propagation between nuclear time steps. Possible options: \newline
	\tabitem [constant] Use the TDCs at $ t + \Delta t$ for all substeps. \newline
	\tabitem [linear] Use linear interpolation between the TDCs at $ t $ and $ t + \Delta t $. \\
	
energy			&
	\textbf{linear} \newline
	Method for interpolation of energies during the propagation between nuclear time steps. \newline
	\tabitem [constant] Use energies at $ t + \Delta t$ for all substeps. \newline
	\tabitem [step] Use energies at $ t $ until $ t + \Delta t / 2$ and energies at $ t + \Delta t $ for the second half of the substeps \newline
	\tabitem [linear] Use linear interpolation between energies at $ t $ and $ t + \Delta t $	\\
	
velocity		&
	\textbf{vel} \newline
	Method of rescaling velocity to conserve total energy after a hop. \newline
	\tabitem [off] No rescaling. \newline
	\tabitem [vel] Uniformly rescale velocity. \newline
	\tabitem [gdif] Rescale velocity along vector given by difference of gradients on initial and final surface. \newline
	\tabitem [nadvec] Rescale velocity along nonadiabatic coupling vector. \\

frustrated		&
	\textbf{reverse} \newline
	Method of treating frustrated hops (hops rejected due to lack of energy). \newline
	\tabitem [continue] Continue trajectory along previous state. \newline
	\tabitem [reverse] Continue trajectory along previous state, but also invert velocity along the direction along which velocity rescaling was attempted. \\

lz\_prob\_conv	&
	\textbf{0.05} \newline
	Attempt to predict uncertainty of the estimated LZ probabilty based on the change in energy when the gap minimum is found and bisect the step until the estimated uncertainty is smaller than the given threshold value. (Set to 1.0 or higher to turn off this behavior.) \\

lz\_min\_dt	&
	\textbf{0.05} \newline
    Minimum time step (in fs) for the lz\_prob\_conv procedure. \\

uncouple\_state		&
	\textbf{none} \newline
	Give list of electronic states which will not be coupled to any others in the surface hopping calculation. When calculating couplings based on overlaps, these states should still be present in the overlap matrix, but all couplings for these states will be set to zero after reading the file. (Example: uncouple\_state 1-2, 5). \\

stop\_s0s1\_ci &
    \textbf{-1.0} \newline
    Stop the trajectory if it reaches a region close to the S$_0$/S$_1$ conical intersection. The trajectory is stopped when $E_1 - E_0 < E_{thr}$ where $E_{thr}$ is given (in eV) by this option. This option is used when potential energies are calculated using single reference methods which give qualitatively wrong results in the S$_0$/S$_1$ CI region. \\
\end{tabularx}


\section*{QM interface} \label{sec:interface}
With the qm keyword, ZagHop runs an external program at every point of the trajectory, in the directory of the trajectory, and communicates with it through two JSON files. ZagHop writes the request qm\_in.json, removes qm\_out.json, runs the command and reads the response qm\_out.json. The program keeps nothing between calls: the overlaps between the states of consecutive points are computed by ZagHop from the wave functions returned by the program, and the signs of the states are matched to those of the previous point. A failed command (nonzero exit status), a missing response or a missing requested quantity stops the trajectory, leaving both files in the directory.

All quantities are in atomic units and states are numbered from 1 within each multiplicity. Geometries, gradients and nonadiabatic coupling vectors are arrays with one inner array per atom (or per coordinate of other coordinate systems, e.g. [[q1], [q2], ...] for normal modes): v[atom][dim]. The request contains:
\begin{tabularx}{\textwidth}{ m{3cm} X }
	protocol, version & "zaghop" and 1. \\
	point\_id & Id of the point. The response must contain the same id. \\
	calculation & "new\_point", or "same\_point" for more quantities at the geometry of the last new point (for example the gradient of the new state after a hop). The program must give the same states as in the new point calculation. \\
	coordinates & Coordinate system of the geometry (classical\_coordinates of the \$system section, by default "cartesian"). \\
	atoms, geometry & Atom symbols (labels of the geometry file) and the geometry. \\
	states & [\{"multiplicity": 1, "nstate": n\}]. \\
	request & "gradients": [\{"multiplicity", "state"\}], "nacv": [\{"multiplicity", "states": [i, j]\}], "wave\_function" (true or false) and "properties" (names of extra quantities, not used by ZagHop).
\end{tabularx}
The response contains:
\begin{tabularx}{\textwidth}{ m{3cm} X }
	protocol, version, point\_id & As in the request. \\
	states & [\{"multiplicity", "energies"\}], the energies of the n states. \\
	gradients & [\{"multiplicity", "state", "gradient"\}] for each requested state. \\
	nacv & [\{"multiplicity", "states": [i, j], "vector"\}], the nonadiabatic coupling vector $\langle i | \partial j / \partial R \rangle$ for each requested pair. \\
	wave\_function & If requested, [\{"multiplicity", "format", ...\}]. Format "vectors": "c", the coefficients of the states in an orthonormal basis which is the same at all points, c[basis][state]. The overlaps of the states of two points are $C_1^T C_2$. \\
	properties & An object with the requested extra quantities.
\end{tabularx}

The program eval\_point answers these requests for the model potentials of the qlib keyword, as a test of the interface and for single point calculations:
\begin{quote}
	eval\_point vibronic\_coupling [template] \newline
	eval\_point model $<$name$>$ [parameter value ...]
\end{quote}
The wave functions are the adiabatic states in the diabatic states of the model. The extra properties are "oscillator\_strengths" (from the first state, for vibronic coupling models with dipole moments), "diabatic\_transformation" (t[diabatic][adiabatic]) and "diabatic\_hamiltonian". zagpy sample state reads the energies, oscillator strengths and diabatic transformation from the qm\_out.json files of eval\_point.

The Python drivers for electronic structure programs in the interface directory do not use this protocol yet.
